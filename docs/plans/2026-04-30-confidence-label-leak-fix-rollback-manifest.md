# Rollback Manifest — Confidence Label Leak Fix (2026-04-30)

This document is the operator-runnable rollback path if the new confidence model produced by the 2026-04-30 leak-fix PR misbehaves.

Backups live under `trained_data/_rollback_2026-04-30/` and are described by `MANIFEST.json` (sha256 verified at backup time).

## What got backed up

- `ridge_confidence.pkl.pre_leak_fix` — old joint confidence model (LightGBM trained against the leaky closed-form formula). R² val = 0.9971, MAE = 0.27.
- `joint_training_meta.json.pre_leak_fix` — old joint metadata from 2026-04-16T11:29:31.
- `confidence_calibration.json.pre_leak_fix` — Platt-scaling JSON (40-trade fit, single `_global` regime).
- `per_pair/{INSTRUMENT}_ridge_confidence.pkl.pre_leak_fix` — 13 per-pair fine-tunes (AUD_NZD, AUD_USD, EUR_AUD, EUR_CHF, EUR_GBP, EUR_JPY, EUR_USD, GBP_AUD, GBP_CHF, GBP_JPY, GBP_USD, USD_CAD, USD_JPY).

`MANIFEST.json` records source path, backup path, file size, source sha256, and backup sha256 for each file.

## Rollback procedure

1. **Stop the scanner.** Kill `buddy` / `buddy_scanner.py` — confidence model is loaded once at startup; live restore needs a clean restart.

2. **Verify backup integrity.**
   ```bash
   cd /home/user/ml_engine
   python3 -c "
   import hashlib, json
   from pathlib import Path
   m = json.load(open('trained_data/_rollback_2026-04-30/MANIFEST.json'))
   bad = []
   for f in m['files']:
       backup = Path('trained_data/_rollback_2026-04-30') / f['backup']
       h = hashlib.sha256()
       with open(backup, 'rb') as fh:
           for c in iter(lambda: fh.read(8192), b''): h.update(c)
       if h.hexdigest() != f.get('sha256_backup'):
           bad.append(f['backup'])
   print('OK' if not bad else f'CORRUPTED: {bad}')
   "
   ```
   Must print `OK`. If corrupted, do not proceed — restore from git instead.

3. **Restore artifacts in place.**
   ```bash
   cd /home/user/ml_engine
   ROLLBACK=trained_data/_rollback_2026-04-30
   cp "$ROLLBACK/ridge_confidence.pkl.pre_leak_fix"           trained_data/models/joint/ridge_confidence.pkl
   cp "$ROLLBACK/joint_training_meta.json.pre_leak_fix"       trained_data/models/joint/joint_training_meta.json
   cp "$ROLLBACK/confidence_calibration.json.pre_leak_fix"    trained_data/confidence_calibration.json
   for f in "$ROLLBACK"/per_pair/*_ridge_confidence.pkl.pre_leak_fix; do
       pair=$(basename "$f" _ridge_confidence.pkl.pre_leak_fix)
       cp "$f" "trained_data/models/${pair}/ridge_confidence.pkl"
   done
   ```

4. **Revert source changes.** The new label generator and loader rewrite live on branch `claude/trading-strategy-analysis-sAakL`. Either revert the merge commit or check out the prior commit:
   ```bash
   git log --oneline trained_data/models/joint/joint_training_meta.json | head -5
   git revert <leak-fix-commit-sha>   # OR
   git checkout <pre-fix-sha> -- src/core/modular_data_loaders.py src/training/labels src/training/trainers/ridge_trainer.py src/training/trainers/joint_trainer.py
   ```

5. **Verify model loads.**
   ```bash
   python3 -c "
   import json
   m = json.load(open('trained_data/models/joint/joint_training_meta.json'))
   r2 = m['metrics']['confidence']['r2_score']
   print(f'r2_score = {r2:.4f}')
   assert r2 > 0.95, 'Restore did not produce leaky-baseline R²; check backups'
   print('OK — leaky baseline restored')
   "
   ```

6. **Restart the scanner.** `./buddy --demo` first, verify confidence scores log without errors and fall in [20, 95]. Then resume normal operation.

7. **Document the rollback.** Append to `.claude/rules/improvement.md` and `.claude/learnings.md` with date, reason, observed metric deltas.

## Partial rollback options

- **New model bad, calibrator OK**: only steps 3 (joint pkl + per-pair pkls) + 4 (revert source). Leave `confidence_calibration.json` as the new version — it will just not match the restored model's distribution and may need a quick refit.
- **Calibrator bad, new model OK**: only restore `confidence_calibration.json.pre_leak_fix`. Note: this will pair the new model with the old calibrator's Platt coefficients (fit against the leaky distribution) — expect degraded calibration quality for hours/days until the live calibrator refits.

## Files NOT covered by this manifest

- `transformer_direction.*` (direction head, untouched by this PR)
- `tcn_volatility_regime.*` (volatility regime, untouched)
- `lgbm_momentum.pkl`, `lgbm_risk.pkl` (untouched)
- Per-pair direction/momentum/risk fine-tunes (untouched)
- `agent_weights.json` (untouched)
- `confidence_calibrator.pkl` if generated by `recalibrate_from_journal()` from `src/risk/confidence_calibration.py` — this is a separate sklearn-pickle calibrator, not the JSON one. It may not exist; if it does and was overwritten, restore from git.

If any of these are corrupted, recover from git history rather than this manifest.

## Follow-up rollback (2026-05-01) — calibration v3, journal backfill, per-pair fine-tunes

The 2026-05-01 follow-up PR (per-pair confidence fine-tunes, W&B
integration, calibration v3, live-journal backfill) extended the
rollback dir with three new backup classes:

- `confidence_calibration.json.v2`     — Platt v2 (pre-v3 state).
- `trade_journal_rl.json.pre_backfill` — live journal before
  24-feature backfill.
- `per_pair/{INSTRUMENT}_ridge_confidence.pkl.pre_per_pair_retrain`
  — 13 per-pair pkls before the 6 follow-up retrains.

`MANIFEST.json` now tracks 31 files; integrity verifier in step 2
above already covers these new entries automatically.

### Partial rollback: revert calibration v3 → v2

If v3 produces degraded calibration (ECE > v2's 0.0166 by a
meaningful margin OR Brier > v2's 0.2140 + 0.05):

```bash
cd /home/user/ml_engine
ROLLBACK=trained_data/_rollback_2026-04-30
cp "$ROLLBACK/confidence_calibration.json.v2" \
   trained_data/confidence_calibration.json
```

### Partial rollback: revert per-pair confidence pkls → pre-leak-fix

If per-pair fine-tunes ship bad scores for a specific pair:

```bash
cd /home/user/ml_engine
ROLLBACK=trained_data/_rollback_2026-04-30
PAIR=AUD_USD   # change as needed
cp "$ROLLBACK/per_pair/${PAIR}_ridge_confidence.pkl.pre_per_pair_retrain" \
   "trained_data/models/${PAIR}/ridge_confidence.pkl"
```

To revert ALL per-pair pkls back to pre-leak-fix state in one go,
use the per-pair backups from the ORIGINAL leak-fix rollback
(`per_pair/${PAIR}_ridge_confidence.pkl.pre_leak_fix`). The
`pre_per_pair_retrain` backups (created 2026-05-01) are identical to
the `pre_leak_fix` backups for the 7 pairs we did NOT retrain (they
weren't touched by either PR), and identical to the previous PR's
`pre_leak_fix` for the 6 pairs we DID retrain (since the previous
PR's "skip per-pair confidence" left those pkls untouched).

### Partial rollback: revert journal backfill

If the backfill output is wrong (e.g. wrong feature builder
selection, wrong instrument one-hot mapping):

```bash
cd /home/user/ml_engine
ROLLBACK=trained_data/_rollback_2026-04-30
cp "$ROLLBACK/trade_journal_rl.json.pre_backfill" \
   trained_data/trade_journal_rl.json
```

Side effect: live trades will lose the backfilled `ridge_features` +
`ridge_features_backfill` provenance tag. New trades going forward
will still populate `ridge_features` correctly through
`modular_inference.py:_extract_ridge_features` (the live runtime path
was never modified).

### Re-extending backups in the future

`scripts/extend_rollback_backups.py` is idempotent — re-run it before
any future PR that touches `confidence_calibration.json`,
`trade_journal_rl.json`, or per-pair confidence pkls. It will:

1. Skip files that already exist with matching sha256 (no-op).
2. Add new backup entries for any file not yet tracked.
3. Atomically update `MANIFEST.json`.
