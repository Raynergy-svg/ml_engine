HOW IT WORKS
================================================================================

FLOW:
  1. Trade closes
     ↓
  2. LearningEngine.analyze_trade() extracts:
     - pair (e.g., "EUR_USD")
     - direction (LONG/SHORT)
     - actual_outcome (True=win, False=loss)
     - confidence (0.0-1.0)
     ↓
  3. accuracy_gate.record_outcome() called
     ↓
  4. Accuracy calculated: wins / total_trades
     ↓
  5. Data persisted to trained_data/pair_accuracy.json
     ↓
  6. Every scan cycle: accuracy_gate.get_blocked_pairs()
     ↓
  7. Merge with scanner.config.blocked_pairs
     ↓
  8. scanner.scan() respects blocked_pairs

BLOCKING LOGIC:
  A pair is BLOCKED when BOTH:
  1. total_trades >= min_trades (default: 5)
  2. accuracy < min_accuracy (default: 0.55 = 55%)
  
  Rationale:
  • 55% is better than 50% random chance
  • If model drops below, it indicates live degradation
  • min_trades=5 prevents blocking after single loss streak

USAGE EXAMPLES
================================================================================

Check pair status:
  from src.scanner.automation.accuracy_gate import AccuracyGate
  ag = AccuracyGate()
  is_allowed, accuracy, reason = ag.check_pair("EUR_USD")
  # Returns: (True, 0.60, "accuracy 60.0% >= 55.0%")

Get all blocked pairs:
  blocked = ag.get_blocked_pairs()
  # Returns: ['GBP_USD', 'AUD_USD']

  # Shows table with all pairs, accuracies, and blocking status

Get pair statistics:
  stats = ag.get_pair_stats("EUR_USD")
  # Returns: {total_trades: 10, wins: 6, accuracy: 0.60, recent_trades: [...]}

Reset pair (after retraining):
  ag.reset_pair("EUR_USD")
  # Clears accuracy history to start fresh evaluation

ERROR HANDLING
================================================================================

All operations wrapped in try/except to prevent crashes:

  Invalid pairs → Logged and skipped
  JSON corruption → Falls back to empty data, logs warning
  Recording failures → Logged at debug level, doesn't interrupt loop
  Integration failures → Wrapped in try/except at both integration points
  
Result: No scenario can crash the scan loop
